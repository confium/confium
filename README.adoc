Confium is an open-source framework that **bridges threshold-cryptography
research to real-world deployment**. It is the substrate on which NIST MPTS
candidate schemes can be implemented once and immediately reach applications
like Mozilla Thunderbird (35M+ users via RNP/OpenPGP).

Funded by Mozilla MOSS and NLNet. Maintained by Ribose. BSD-2-Clause.

== Demonstrate it

[source,sh]
----
# Run the full ecosystem demo
./demo.sh

# Or run individual demos:
cargo run -p confium-examples --bin threshold_signing    # 3-party TC signing
cargo run -p confium-examples --bin plugin_load_and_hash # plugin loading
cargo run -p confium-examples --bin keystore-roundtrip   # key storage
cargo run -p confium-examples --bin audit_log_stream     # audit events
----

The threshold signing demo proves the core value proposition: three parties
collaborate to produce a single valid signature, with no party holding the
complete secret key.

== What Confium provides

[cols="1,4,1"]
|===
| Pillar | What | Crates

| **Engine**
| Plugin loader (OCP-compliant via link-time registry), 8 crypto interfaces
(hash, RNG, cipher, AEAD, KDF, signature, KEM, key serialization),
error source chain, sensitive/secret memory, audit logging
| `confium-core`, `confium-api`, `confium-macros`

| **Store**
| Compartmentalized key/secret persistence with public/private isolation.
Backends: memory, filesystem, PKCS#11 (HSM), TPM 2.0, Cloud KMS
(AWS/GCP/Azure)
| `confium-store`, `confium-store-{pkcs11,tpm,cloud}`

| **Network**
| Transport abstraction for multi-party TC protocols.
Transports: in-process, mock, TCP, QUIC, WebSocket
| `confium-net`, `confium-net-{tcp,quic,ws}`

| **Threshold Crypto**
| Session lifecycle (create/round/result), party roster, share management.
Real schemes: FROST-ed25519, GG18-ECDSA, CMP20-ECDSA, plus mock.
NIST evaluation harness with byzantine peer simulation.
| `confium-tc`, `confium-tc-{frost-ed25519,gg18,cmp20}`, `confium-test-harness`

| **Registry**
| Static-site plugin catalog (GitHub Pages). Publisher-signed manifests,
trust-root model. Client fetches/verifies/installs. Author tool signs and
publishes.
| `confium-registry`, `confium-publish`, `sites/registry/`

| **CLI + Daemon**
| End-user: install/remove/list/search/trust/config. JSON-RPC daemon for
app integration.
| `confium-cli`, `confium-daemon`

| **Sandbox**
| Plugin isolation: WASM (wasmtime with capability model) and out-of-process
(subprocess IPC).
| `confium-sandbox-{wasm,process}`
|===

== Architecture

The four pillars compose: a 2-of-3 threshold signing session loads shares
via the **Store**, opens transports via the **Network**, runs rounds via
the **Engine**'s TC interface, and emits audit events throughout.

== Plugin contract (OCP-compliant)

Adding a new interface type = writing a module that calls `register_interface!`.
Zero edits to existing code. Powered by the `inventory` crate (link-time
registration).

[source,rust]
----
// In src/ffi/my_interface.rs
pub struct MyKind;
impl PluginInterfaceKind for MyKind {
    fn name(&self) -> &'static str { "my-interface" }
    fn max_version(&self) -> u8 { 0 }
    fn build(&self, lib: &Library, version: u8) -> Result<Option<Rc<dyn Any>>> { ... }
}
register_interface!(MyKind);
// Done. The plugin loader now discovers this interface automatically.
----

Or use the proc-macro SDK:

[source,rust]
----
#[plugin_interface(name = "hash", version = 0)]
impl HashPlugin for MyHasher {
    fn create(&self, algo: &str) -> Result<Self> { ... }
    fn update(&mut self, data: &[u8]) -> Result<()> { ... }
    fn finalize(&mut self) -> Result<Vec<u8>> { ... }
}

#[export]
#[plugin_metadata(name = "my-hash", version = "1.0", vendor = "acme")]
struct MyPlugin;
----

== Algorithm coverage

Confium's framework supports every algorithm class that RNP covers:

[cols="2,5"]
|===
| Hashes | MD5, SHA-1, RIPEMD-160, SHA-224/256/384/512, SHA3-256/512, SM3
| Symmetric | IDEA, 3DES, CAST5, Blowfish, AES-128/192/256, Twofish, Camellia, SM4
| AEAD | EAX, OCB, GCM, ChaCha20-Poly1305
| Signatures | RSA, DSA, ECDSA, EdDSA, Ed25519, Ed448, SM2 + PQC composites
| KEMs | RSA-OAEP, ECDH (P-256/384/521, X25519, X448), SM2 + Kyber composites
| KDFs | HKDF, PBKDF2, Argon2, Scrypt, OpenPGP S2K
| Threshold | FROST-ed25519, GG18-ECDSA, CMP20-ECDSA (+ mock scheme)
| PQC | ML-KEM, ML-DSA, SLH-DSA, Kyber/Dilithium composites
|===
