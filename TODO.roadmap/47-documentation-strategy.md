# 47 — Documentation strategy

## Audience tiers

| Audience | Doc | Where |
|---|---|---|
| **Curious visitor** | Landing page, "what is Confium" | https://confium.org (Jekyll) |
| **Evaluator** | "Why use Confium", case studies, security model | Project docs (AsciiDoc) |
| **Developer** | Quickstart, API docs, examples | docs.rs + docs/ |
| **Plugin author** | Plugin contract, FFI spec, examples | `TODO.roadmap/43-plugin-author-guide.md` + docs/plugin-author-guide.adoc |
| **Operator** | Deployment guide, manifest reference | docs/deploy.adoc |
| **NIST evaluator** | NIST Evaluator Guide, MPTS submission | docs/nist-evaluator.adoc |
| **Researcher** | Algorithm specs, paper references | docs/research/ |

## Documentation surfaces

### 1. docs.rs (auto-generated from source)

Every published crate gets a docs.rs page. Each `pub` item has a doc comment.
Generated on every release via `.github/workflows/rustdoc.yml`.

### 2. AsciiDoc project documentation (`docs/`)

- `docs/index.adoc` — landing page
- `docs/develop.adoc` — developer guide
- `docs/deploy.adoc` — operator/deployment guide
- `docs/plugin-author-guide.adoc` — plugin author tutorial
- `docs/nist-evaluator.adoc` — NIST MPTS submission guide
- `docs/security-model.adoc` — security analysis (from `TODO.roadmap/08`)

Deployed via `.github/workflows/docs.yml` to GitHub Pages.

### 3. Jekyll site (https://confium.org)

- Top-level: "What is Confium", "Three deployment modes", case studies
- OIML CNML case study (Mode 3 flagship)
- Blog posts: research contributions, NIST submissions, deployments
- "Get started" → docs.confium.org

### 4. README.md per crate

Each published crate has a `README.md` with:
- One-paragraph purpose
- Install snippet
- Minimal usage example
- Pointer to docs.rs for full API

### 5. Examples (`crates/confium-examples/`)

Each example has a doc comment explaining what it demonstrates. See
`TODO.roadmap/45-integration-examples.md` for the inventory.

### 6. CHANGELOG.md (auto-generated by release-plz)

Driven by conventional commits. Per-crate changelogs auto-published
to GitHub Releases.

## Writing principles

- **Show, don't tell** — examples over prose
- **Verifiable** — every code snippet compiles (`cargo test --doc`)
- **Audience-aware** — different tone for evaluator vs developer
- **Linked** — every doc cross-references related docs (TODO.roadmap
  references are bidirectional)

## Documentation types

### Conceptual ("What is X?")

For each major concept:
- Threshold signing, threshold encryption
- OCP plugin registry
- Three deployment modes
- Share re-sharing
- Async coordinator
- Composite signatures (PQ migration)
- Transparency log

Each gets a dedicated `.adoc` file in `docs/` plus an entry in the relevant
`TODO.roadmap` doc.

### Procedural ("How do I do X?")

For each common task:
- Install Confium
- Install a plugin
- Generate a threshold keypair
- Run a 2-of-3 signing ceremony
- Deploy a coordinator service
- Configure PKCS#11 server
- Write a new plugin

These live in `docs/` as numbered tutorials.

### Reference ("API for X")

Auto-generated by rustdoc. Each crate's `pub` API is its reference.

## Maintenance

- Documentation updates required for every PR that changes user-facing API
- Pre-commit hook checks that `cargo doc` runs clean
- `typos` catches spelling errors
- Quarterly review: every doc reviewed for accuracy

## Anti-goals

- **Not** publishing internal implementation docs (those live in code comments)
- **Not** maintaining separate "spec" and "implementation" docs (the code IS the spec)
- **Not** generating docs from external tools (use rustdoc)
