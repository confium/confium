# 73. WASM Bindings Roadmap

**Status:** Phase 2A scaffolded on `feat/wasm-verifier-crate` branch.
Verifier-only by design — browsers verify, servers sign.

**Principle:** `@confium/confium-wasm` is a single npm package, built
with `wasm-pack`, exposing a tree-shakable surface gated by
`verify-*` Cargo features. Each feature is a verifier domain. Signers,
issuers, threshold sessions, and key material never enter the browser.

## Phasing

### Phase 2A — scaffold + composite + transparency + attributes (current PR)

- New crate `crates/confium-wasm/`
- `wasm-bindgen` + `js-sys`, target `wasm32-unknown-unknown`
- Feature flags: `verify-composite`, `verify-transparency`, `verify-attributes` (all on by default)
- `CompositeSignature.from_json(json)` + `.verify(message)` + `CompositeVerificationResult`
- `MerkleTree.new()` + `.append(artifact_hash)` + `.root()` + `.length` + `.inclusion_proof(seq)` + `InclusionProof.verify(root)`
- `Predicate.parse(expr)` + `.satisfied_by(signers_json)`
- `version()`, `core_version()`
- Update `.github/workflows/wasm.yml` to build `crates/confium-wasm` (was building the sandbox crate)
- `wasm-bindgen-test` smoke tests in `crates/confium-wasm/tests/`

### Phase 2B — verifier callbacks + XMLDSig

- `CompositeSignature` gains an optional per-component verifier callback
  in JS (so consumers can plug in their own ML-DSA-65 verifier once the
  Rust crate ships).
- `Certificate.from_der(der_bytes)` + `.from_pem(pem_string)` +
  `CertificatePath.validate(leaf, intermediates, root)`.
- `CMSSignedData.from_der(der_bytes)` + `.verify(certificates_der)`.
- `XMLDSig.verify(xml_string, certificates)` with Exclusive C14N.
- TS types generated by `tsify` or `wasm-bindgen`'s built-in.

### Phase 2C — transparency verify-only helpers

- `MerkleTreeHead.from_json(json)` (the server publishes tree heads).
- `verify_inclusion(head, leaf, proof)` standalone function.
- `verify_consistency(old_head, new_head, proof)` for tree updates.

### Phase 2D — npm package

- `wasm-pack build --target bundler --scope confium` produces ESM + CJS.
- `package.json` with `sideEffects: false` for tree-shaking.
- Type definitions (`.d.ts`) emitted from `tsify` or hand-written.
- Publish to npm via `wasm.yml` on release tags.
- README with usage examples for Vite, Webpack, Next.js, Node.

### Phase 2E — Node.js native crypto adapter

- Replace `getrandom` `js` feature with a Node.js adapter when running
  outside the browser (Node 18+ has `crypto.webcrypto`).
- Optional: `--target nodejs` build of the package for environments
  where ESM + web crypto isn't available.

## Verifier callback contract

For algorithms the Rust crate doesn't yet implement (e.g. ML-DSA-65,
SLH-DSA), the WASM surface lets the JS caller supply a verifier:

```js
const sig = CompositeSignature.from_json(json);
const result = sig.verify(messageBytes, {
  // Optional per-component verifier. Called for any component whose
  // algorithm isn't natively supported. Default: only Ed25519 is supported.
  "ML-DSA-65": async (publicKey, message, signature) => {
    // caller-supplied ML-DSA verifier (e.g. via WebCrypto ML-KEM API once standardized)
    return true;
  },
});
```

This keeps the WASM blob small (no PQ crypto pulled in until standards
stabilize) while letting consumers add verifiers incrementally.

## Anti-patterns

- **Never expose signing keys** through the WASM surface. If a class
  would need to hold a private key, it doesn't belong in this crate.
- **Never expose the plugin engine** — plugins require dynamic loading,
  which is impossible in `wasm32-unknown-unknown` anyway.
- **Never expose `confium-core` directly** — its `Confium` struct is a
  plugin registry, not a verifier API.
- **Never assume browser context** — design for Node.js + browser +
  edge runtimes (Cloudflare Workers, Deno).
- **Never use `tokio` or filesystem-touching crates** in this crate's
  dependency closure. Audit via `cargo tree --target wasm32-unknown-unknown`.

## Performance

- LTO + opt-level=3 in release profile.
- Codegen-units=1 for best single-call latency (browsers block on verify).
- Consider `wee_alloc` for smaller binary (default allocator is ~10KB
  larger).
- Bench against equivalent pure-JS verifiers (`@noble/curves`,
  `@noble/hashes`) — must be within 2× of native, ideally <1.5×.
